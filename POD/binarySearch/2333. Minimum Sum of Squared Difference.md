# DSA Notes: Binary Search on Answer

**Problem:** Minimum Sum of Squared Difference  
**Pattern:** Binary Search on Answer + Greedy  
**Difficulty:** Hard

## 1. Why do we need optimization?

In the brute-force/heap approach, we reduce the largest difference by 1 for every operation.

If `k = 1,000,000,000`, performing a billion operations is too slow and causes TLE.

**Optimization:** Instead of reducing one by one, search for a target maximum difference.

## 2. Main intuition

Suppose:

`diff = [8, 5, 3]`, `k = 3`

We want to find the smallest target such that every difference can become less than or equal to that target using at most 3 operations.

Example:

- Target = 4 → needs 5 operations → impossible.
- Target = 5 → needs 3 operations → possible.
- Target = 6 → needs 2 operations → possible.

The smallest feasible target is 5.

**Important:** We apply binary search to possible target values, not to the elements of the difference array.

## 3. How to calculate operations needed?

Formula:

`needed += max(0, diff[i] - target)`

Example: `diff = [8, 5, 3]`, target = 5

- 8 needs `8 - 5 = 3` operations.
- 5 needs 0 operations.
- 3 needs 0 operations.

Total needed = 3.

## 4. Binary search logic

Initial range:

`low = 0`, `high = maximum difference`

Calculate:

`mid = low + (high - low) / 2`

If `needed <= k`:
- Target is feasible.
- Try a smaller target: `high = mid`.

If `needed > k`:
- Target is impossible.
- Try a larger target: `low = mid + 1`.

Stop when `low == high`.

## 5. Why do we calculate the final sum separately?

Binary search finds a feasible target; it does not directly calculate the minimum squared sum.

After finding the target:
1. Reduce every difference above the target to the target.
2. Calculate the squared sum.
3. Use remaining operations to reduce some differences further.

For example:

`[7, 7, 7, 7, 7]`, `k = 9`

- Reduce all five 7s to 6: 5 operations.
- Four operations remain.
- Reduce four 6s to 5.

Final differences: `[5, 5, 5, 5, 6]`

Squared sum = `4 × 25 + 36 = 136`.

## 6. When should I recognize this pattern?

Use Binary Search on Answer when:
- You are searching for the minimum or maximum possible value.
- You can check whether a candidate answer is feasible.
- Feasibility is monotonic: if one target works, all larger targets work (or vice versa).

## 7. Common mistakes

- Confusing the target values with array elements.
- Forgetting to count operations for every difference greater than the target.
- Using `int` for large operation counts or squared sums.
- Returning the squared sum before accounting for remaining operations.
- Treating “at most k” as “exactly k”.

**Complexity:** `O(n log M)` time and `O(n)` space, where `M` is the maximum absolute difference.

**One-line takeaway:** Binary search finds the smallest feasible maximum difference; the final adjustment minimizes the sum of squares.


Edge Cases — Minimum Sum of Squared Difference

1. Both arrays are identical

Example:

diff = [0, 0, 0]

k1 = 2, k2 = 3

All differences are already zero.

Condition: sumOfDifferences == 0
Answer: 0

2. Operations are enough to eliminate all differences

Example:

diff = [2, 1]

k1 + k2 = 3

Total difference = 2 + 1 = 3.

Since the operation budget is at least the total difference, all differences can become zero.

Condition: sumOfDifferences <= k1 + k2
Answer: 0
